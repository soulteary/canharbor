# ADR 0001 本地 Rust 服务与 Web UI

日期：2026-11-05。状态：方案采用，已按此实现；实机验证尚未完成，见 [status.md](../status.md)。

## 背景

CANHarbor 面向 macOS CAN/CAN FD 用户，需要同时服务 CLI、浏览器和将来的 SDK/绑定。USB 多通道与多进程抢占需要统一所有权；用户明确选择 Web UI。浏览器生命周期和定时器不适合作为采集、落盘和发送调度的可靠基础。

## 决策

使用一个 `canharbor` 可执行文件，由 `serve` 子命令启动本地 Rust 服务。CLI 经 UDS、浏览器经 loopback HTTP/WS 连接该服务；服务独占每个 USB 设备并按通道分发。Rust SDK 仍可直接嵌入核心，但必须与服务协调设备占用。

HTTP 处理配置和控制，WS 只传只读批量事件。默认精确绑定 127.0.0.1 的动态端口，同源提供 React/TypeScript 静态 UI，发行时编入二进制。使用一次性配对、cookie、CSRF、精确 Origin/Host 校验保护本地硬件入口。

通道控制基于单一可过期 lease，所有有副作用操作使用 fencing。暂停 UI 不暂停采集；客户端慢速独立丢弃并报告 gap。断线、重启和重插不会自动恢复主动发送。服务端录制与浏览器显示分离，但仍服从通道生命周期。

## 备选与取舍

浏览器直接 WebUSB 会引入浏览器支持、权限和设备所有权差异，也无法统一 CLI 访问，不作为首版设备路径。桌面 WebView 包装增加签名、更新和壳层维护，首版不需要。云端托管 Web UI 会使本机服务跨源、安全及离线流程复杂化，不作为默认入口。

先用 JSON 而非二进制 WS 降低契约复杂度；以批量、队列和基准控制开销，测量后再决定是否升级协议。先用静态后端注册而非动态插件 ABI，降低生命周期与许可治理成本。

## 后果与重审条件

启动服务成为 CLI 设备操作的前置条件；本地端口也需要认证。前端构建增加 Node 工具链，但普通用户与核心 SDK 不依赖 Node。额外服务 crate 和 API DTO 避免 UI 与驱动互相耦合。

若需要远程共享、浏览器退出后长期主动任务、系统 SocketCAN ABI 或远超 JSON 基准的数据率，应分别建立新 ADR，不通过放宽现有认证、关闭 lease 或扩大无界缓存解决。
